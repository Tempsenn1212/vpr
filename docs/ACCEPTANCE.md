# Проверка критериев приёмки

Дата: 11.11.2026. Использованы только синтетические пользователи и подписанные тестовые Telegram payload. Реальных аккаунтов, токена бота и домена нет; внешний запуск в Telegram не объявляется проверенным.

## Итог

- `npm test`: **32/32**, доменные и HTTP-интеграционные тесты, 0 ошибок.
- `npm run build`: TypeScript и production-сборка Vite — успешно.
- Playwright / системный Chromium: **7/7** сценариев, включая два независимых контекста и обновление за 5 секунд.
- Docker: образ собран, контейнер запущен непривилегированным пользователем; health 200; карточка и аудит сохранились после перезапуска контейнера.
- `docker compose config --quiet`: успешно; отдельно проверен образ и его запуск, весь Compose-стек не поднимался.
- Резервирование: SQLite backup API, проверка целостности и восстановление на новой БД — успешно, отдельный автоматический тест.
- `npm audit`: 0 известных уязвимостей в установленных зависимостях на момент проверки. Это не аудит безопасности всего приложения.

## Семь браузерных сценариев

1. Два клиента: создание → появление без reload → оформление другим участником → правильное имя исполнителя; у работника нет кнопки подтверждения.
2. Мобильный экран: ошибки обязательных полей, длинное название, вложение, копия с пустым сроком, тёмная тема, удаление и просмотр истории удалённой карточки.
3. Начальник: выбор категории/всех PLACED, исключение карточки, фиксация проверки и событие в истории.
4. Обрыв API-запросов: форма и ошибка вместо успеха, восстановление связи и сохранение.
5. 360 px: пустой поиск, светлая тема, отсутствие горизонтального переполнения.
6. Две формы: чужая сохранённая правка не перезаписывается; черновик остаётся; явная загрузка текущей версии.
7. Управление: добавление участника и категории, расчёт расписания; администратор с ролью работника не получает подтверждение.

## Что остаётся проверить с реквизитами

Реальный запуск через BotFather/бота, HTTPS-домен и reverse proxy, Telegram iOS/Android/Desktop/Web, обработка темы и ограничения cookies в конкретных клиентах. Тест HMAC использует синтетический подписанный пакет, а не данные реального Telegram. Нагрузочное тестирование большой базы не проводилось; текущее обновление передаёт полный набор карточек и аудита для небольшой рабочей группы.

Исходный код, миграции и инструкции готовы для локального запуска. Общедоступное размещение не выполнялось.
