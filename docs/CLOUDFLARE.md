# Бесплатный автономный запуск на Cloudflare

Приложение запускается на **Workers Free** с постоянной **SQLite в Durable Object** и минутным Cron Trigger. Компьютер, локальный сервер и ngrok после переноса не нужны. Интерфейс и `/api` работают на одном HTTPS-адресе `https://vpr-document-tracker.<поддомен>.workers.dev`.

Вместо ранее предложенной отдельной D1 выбрана SQLite внутри Durable Object: это сохраняет синхронные транзакции существующего приложения, атомарную отметку 40 листов, аудит, версии и защиту от повторных операций. SQLite-backed Durable Objects доступны на бесплатном тарифе. Платный тариф команда настройки не подключает.

## Первоначальный запуск с Windows

1. Установите Node.js 24 LTS и Git, если их ещё нет. Аккаунт Cloudflare должен быть зарегистрирован, почта подтверждена. В Cloudflare откройте **Workers & Pages** и настройте поддомен `workers.dev`, если аккаунт попросит его создать. Не подключайте Workers Paid.
2. Остановите локальный сервер через Ctrl+C, чтобы после переноса не вести два независимых журнала. Сохраните исходную папку `data` целиком; команда дополнительно сделает JSON-копию перед переносом.
3. Откройте PowerShell. Все команды выполняйте в папке проекта:

   ```powershell
   Set-Location "C:\Projects\vpr"
   git pull --ff-only origin main
   npm.cmd ci
   notepad .env
   ```

   В существующем `.env` проверьте две строки; не заменяйте весь файл этими примерами:

   ```dotenv
   BOT_TOKEN=ТОКЕН_ВАШЕГО_БОТА
   INITIAL_ADMIN_TELEGRAM_ID=ВАШ_ЧИСЛОВОЙ_TELEGRAM_ID
   ```

   Нужен настоящий числовой Telegram ID, а не `@username`. Токен останется локально в `.env` и будет передан как секрет Cloudflare; в GitHub он не добавляется. Настройки локального `APP_ORIGIN` и `DEV_AUTH` в облако не копируются.

4. Запустите подготовленную команду:

   ```powershell
   npm.cmd run cloudflare:setup
   ```

   Команда предложит путь к существующей SQLite-базе или JSON-копии, скачанной из приложения. Если путь совпадает с показанным, нажмите Enter. Обычно это `data/vpr.sqlite`. Для намеренно пустой новой базы введите **НОВАЯ**. Несуществующий файл не заменяется пустой базой автоматически.

   Если старая база была демонстрационной, команда отдельно предложит перенести все её документы и историю, отключить тестовые аккаунты и назначить введённый настоящий Telegram ID единственным активным администратором. Подтвердите словом **ДА** только если хотите сохранить эти записи, включая демонстрационные. Исходная база не изменяется при таком преобразовании; конвертируется её копия. Остальных настоящих участников после этого можно включить в «Управлении».

5. Wrangler откроет браузер. Войдите в созданный аккаунт Cloudflare и разрешите доступ. Затем команда соберёт интерфейс, опубликует Worker, передаст секреты, проверит API и при необходимости перенесёт базу. Если Cloudflare попросит выбрать аккаунт или настроить поддомен, выполните это в его интерфейсе и повторите команду.
6. В конце будет показан **реальный HTTPS-адрес**. Откройте `<этот адрес>/api/health`: ответ должен содержать `"ok":true`, `"migrationPending":false`. В этой же папке есть `.cloudflare-setup.json` с адресом и результатом настройки — файл исключён из Git.
7. В `@BotFather` выберите бота через `/mybots`. Замените URL в **Bot Settings → Menu Button**. Если Mini App настроен отдельно через `/newapp` или Main Mini App, обновите его URL тоже. Указывайте адрес приложения **без** `/api/health`.
8. Закройте Mini App полностью и откройте кнопкой бота. Проверьте документы, темы, участников и отметки. После этого выключите компьютер и откройте приложение на телефоне. Оно должно продолжать работать.

До завершения первоначального импорта облачная авторизация и генерация карточек приостановлены. Ошибка импорта откатывается целиком. Исходная база и JSON-копия остаются локально. Для одноразового импорта установлен предел 20 МБ; большая копия требует поэтапного переноса и будет отклонена до публикации. Повтор того же импорта безопасен; замена уже заполненной облачной базы другой копией запрещена. После успешного импорта временный секрет переноса удаляется.

Если команда прервётся, устраните указанную причину и повторите `npm.cmd run cloudflare:setup`. Не удаляйте `.cloudflare-setup.json` и папку `backups`, пока перенос не завершён. Файл состояния может временно содержать одноразовый секрет импорта — не публикуйте его.

## Предупреждения установки npm

Если `npm ci` пишет `EBADENGINE` и показывает Node.js 26, установка могла завершиться, но версия не соответствует проекту. Требуется именно **Node.js 24.x**, а не автоматически выбранный новый LTS другой основной версии. Установите Windows Installer Node.js 24 с официального сайта, закройте PowerShell и откройте заново. `node --version` должен начинаться с `v24.`. Если установщик отказывается заменить более новую версию, сначала удалите Node.js 26 через установленные приложения Windows. Рабочая папка проекта и база от переустановки Node.js не удаляются.

В `package.json` явно разрешены установочные скрипты закреплённых `esbuild@0.28.2` и `workerd@1.20261123.1`, необходимых для сборки и локальной среды Cloudflare. Получите обновление через Git и повторите `npm ci`. Не требуется разрешать все скрипты или вручную править манифест. Политика проверена с npm 11.20.0 и `--strict-allow-scripts`.

Предупреждение `deprecated node-domexception` относится к транзитивной зависимости, а `npm notice` предлагает обновить npm. Они сами по себе не означают провал установки и не требуют обновления npm до следующей основной версии. Если команда завершилась успешно, после проверки Node.js и переустановки зависимостей продолжайте `cloudflare:deploy`.

## Последующие обновления

В PowerShell из `C:\Projects\vpr`:

```powershell
git pull --ff-only origin main
npm.cmd ci
npm.cmd run cloudflare:deploy
```

URL и база сохраняются. Настройка ролей и прав после обновления описана в [ROLES.md](ROLES.md). Не удаляйте Worker/Durable Object в панели Cloudflare, не меняйте имя класса `VprDatabase`, привязку `VPR_DB` и ключ объекта `vpr-main` для «переустановки»: это может отсоединить существующую базу.

Расписания исполняются облачным Cron Trigger каждую минуту. Cloudflare использует UTC, а даты документов рассчитываются в `Europe/Moscow`. Настройка или изменение cron может распространяться до 15 минут. Повторный запуск не создаёт дублей, пропущенные периоды восстанавливаются. В облаке нет постоянно запущенного `setInterval`.

## Копии и восстановление

Администратору рабочей базы доступно **Управление → Резервная копия → Скачать резервную копию**. JSON содержит документы, пользователей, историю, правила и снимки проверок, но не сеансы входа и не токен бота. Храните копии отдельно от Cloudflare. Автоматическая отправка копий во внешнее хранилище не настроена.

Восстановление выполняется при первоначальной настройке нового пустого Worker: запустите `cloudflare:setup` и укажите путь к JSON-копии вместо SQLite-файла. Не очищайте рабочую базу ради проверки. Импортный API принимает формат `vpr-portable-v1` только при наличии временного секрета и только в пустую базу. Существующие данные автоматически не заменяются.

Для дополнительной копии рабочей локальной SQLite, без публикации:

```powershell
npm.cmd run cloudflare:export
```

Команда сохраняет `backups/cloudflare-migration.json` и откажется перезаписать существующий файл. Демонстрационная база переносится только через явное подтверждение в `cloudflare:setup`.

## Бесплатные лимиты и ограничения

Бесплатность действует в пределах квот аккаунта. У Workers Free — 100 000 динамических запросов в день; у SQLite Durable Objects есть отдельные лимиты запросов, активного времени, чтения/записи и объёма хранения. При превышении бесплатных лимитов операции могут временно перестать работать; автоматического перехода на платный тариф этот проект не делает. Точные текущие квоты смотрите в панели и официальной документации.

В облаке открытая Mini App обновляет данные каждые 15 секунд; в скрытой вкладке опрос приостановлен и возобновляется при возвращении. Локальная версия сохраняет интервал 2 секунды. Количество одновременно постоянно открытых окон, полный аудит и рост базы влияют на расход квот; большой архив потребует дополнительной оптимизации запросов. GitHub Pages не исполняет этот API и не заменяет Workers.

Проверьте доступность итогового `workers.dev` адреса именно с сетей и устройств ваших пользователей до окончательного отказа от локального запуска. Бесплатный поддомен не равен гарантии доступности из любой сети.

## Проверки разработчика

```powershell
npm.cmd test
npm.cmd run test:cloudflare
npm.cmd run build
npx.cmd wrangler deploy --dry-run
```

`test:cloudflare` запускает локальный настоящий runtime Workers/SQLite, тестирует подпись Telegram, cookies/Bearer, права, транзакции, конфликты, темы, 40 листов, cron без открытого приложения, перезапуск, перенос и скачивание копии. Браузерный сценарий требует Chromium (`CHROMIUM_PATH`; на Linux по умолчанию `/usr/bin/chromium`). Пользователю для публикации запускать эти тесты не требуется.
